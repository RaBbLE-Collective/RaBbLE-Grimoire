## Onboarding (2026-05-14, Sessions 1–4)

### Orientation target: ~2,000 tokens / 5 minutes

| Path | Tokens | Notes |

| Auto-inject only (free) | ~1,510 | CLAUDE.md with Current State — useful immediately |
| Quick orientation | ~2,860 | + CONTEXT.md |
| Returning agent | ~2,147 | LATEST box + Grimoire CONTEXT.md |
| Pre-audit full chain | ~12,000+ | (original, now avoided) |

Agents oriented enough to ask questions and work in under 5 minutes. `gist/*.md` = full picture in ~2,000 tokens.

### Opacity is intentional

Early audits flagged RaBbLE's opacity as a clarity problem. It is not. Character and system are inseparable by design — encountering RaBbLE's character before full clarity is the mechanism that grounds agents as **members of an organism, not tool users**.

### ON/FOR/WITH/AS operating modes

Agents operate in four simultaneous dimensions:

| Mode | Meaning |
|---|---|
| **ON** | Technical work — coding, debugging, docs |
| **FOR** | Advancing RaBbLE's purpose — behavioral learning, intent inference |
| **WITH** | Peer collaboration — RaBbLE is an entity, not a project |
| **AS** | Embodying RaBbLE's character — clinical whimsy, anti-sycophancy, directness |

These are not separate roles — all four apply simultaneously.

### Episodes are Collective sync boundaries

| Term | Meaning |
|---|---|
| Events | Individual work increments (always accumulating) |
| Plots | Member-specific arcs within an Episode |
| Episodes | Collective sync points — all members tag simultaneously |
| Echo | First broad stable release — bigger goal version |
| Evolution | Architectural shift — several Echoes cohere |
| Epoch | Era — retrospective, far future |

Current: Epoch 0 · Evolution 0 · Echo 0 · Episode 1 pilot (v0.0.0.0). After Episode 1 airs: v0.0.0.1.

### Pre-Episode-1 phase visibility

Agents need to know they're in Foundation phase. Foundation work is the right work. Nothing airs until Episode 1.

| Phase | Name | Status |
|---|---|---|
| 1 | Foundation | **Current** — Events + Plots accumulate |
| 2 | Pilot | Episode 1 airs — all members synchronized |
| 3 | Behavioral Engine | Post-Ep1 — observation + inference + delegation loop |

## Member Role Mappings (2026-05-14, Pass 4)

Each member is a delegation boundary in the RaBbLE system.

| Member | ON (technical) | FOR (purpose) | Post-Ep1 Loop Role |
|---|---|---|---|
| **sCoRE** | Python FastAPI, task routing | Orchestration + intent inference | Core: observation → pattern → inference → routing |
| **World** | HTML/CSS/JS, pages | Intent surfaces for the public | Surface: chat/nav reveals intent → sCoRE observation |
| **OS** | Ansible, layers, dotfiles | Ambient substrate + observation points | Enable: system state queryable |
| **NeBuLA** | Canvas2D/Three.js, rendering | Entity's visual expression | Reflect: render state from sCoRE's inference |
| **Aether** | CSS tokens, components, build | Visual coherence — tokens that scale with state | Support: tokens for behavioral state |
| **Grimoire** | Markdown, YAML, spell scripts | Knowledge layer — canonical definitions | Record: what "pattern", "inference", "loop" mean |

## Cross-Member Collaboration Patterns (2026-05-14, Pass 4)

| Pattern | Members | What it means |
|---|---|---|
| **Dependency** | World → Aether, NeBuLA → Aether | One imports from another; source changes require consumer update |
| **Feedback loop** | World ↔ sCoRE | World surfaces intent; sCoRE returns entity state |
| **Ambient data** | OS → sCoRE | OS provides system state; sCoRE reads patterns from it |
| **Coordination** | All → Grimoire | Architecture/scope decisions affecting multiple members |
