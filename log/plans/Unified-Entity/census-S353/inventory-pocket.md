## Corrections / findings against the plan
1. Plan row "Pocket web SVG entity ... retire": correct, but `orbit.js` and `portal.js` depend on `PocketEntity.meshSide/backdrop/snapshot/look/audio/setQuality` (list in table row 8/9). Retire order: NeBuLA gains those APIs, then `portal.js` switches, then delete `pocket-entity.js` + `build-entity.py` (plan U5 says exactly that; fine).
2. The plan's "BaBbLE intake and Xperimental drop" copies of the Pocket mock are both md5 8e55286e, identical to each other and one line (the Accord header comment) behind Pocket's mock. True drifters, no unique content.
3. Missed by the plan: `entity_face.c/.h` (dead LVGL face, third proportion set; the constants `ENTITY_*` hand-copied from NeBuLA ratios), `rabble_entity.c` (input mapping), `rabble_orbit*.c` (device Orbit), `portal.js` Foundling circles, `sim/` harness files.
4. No infinity flow exists in any Pocket file (no match for infinity/lemniscate). Pocket draws two portals with a mesh and mic strands, not an infinity path between portals. So "infinity" is rig-only (Puppet Spec) and the registry will need an explicit per-surface support entry (Pocket = none or mesh substitute).
5. Pocket proportions differ internally: mock portal `rx44 ry11` (4:1, `mock:170`) vs `entity_face.h` `106x33` (3.2:1) vs rig 2.69 eye-widths. Registry should take the mock/scene.c pair as Pocket profile; `entity_face.h` ones are stale.
6. Stale comment: `scene.c:3` says renderer lives in `sdk/rabble_render`; it is `entities/RaBbLE/nebula_lite`. `rabble_ui.c:3-9` describes an old canvas rasteriser; the face is now drawn by `rabble_entity.c` + nebula_lite.
7. Publication: only `public/` (pocket-entity.js, orbit.js, portal.*, fonts) is served by worker `rabble-pocket-companion` at `pocket.joinrabble.world` (`wrangler.jsonc`); BLOCKERS B-41 says not yet deployed with the latest code. I did not hit the network to verify.
