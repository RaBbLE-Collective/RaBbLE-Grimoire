## What the plan missed / corrections to its rows
1. The plan lists `canvas2d-backend.js` as a body of code. It is a 2-line re-export shim (src/backends/canvas2d-backend.js:1-2); real code is canvas2d/index.js. Same for backends/index.js.
2. `src/backends/eye-behavior.js` is missing from the plan and is the most important file for unification: it holds the constants every other copy should be measured against (eye-behavior.js:25-33).
3. alive-backend.js is not "an emotion layer on top". It is a **third, independent entity renderer** (own geometry, own boot, own moods, 2D and 3D) sharing nothing with canvas2d/threejs except palette.js and three-loader. The Portal runs on it, not on the "canonical" Canvas2D row.
4. Missed rows: src/ui/grimoire-eye.js, grimoire-ring.js, entity-mini.js (drifters), src/puppet/palette.js, src/core/boot-sequence.js, examples/alive.html + test/alive.*.mjs, specs/visual-spec.md (Aether twin).
5. specs/rig/entity-rig-demo.html is NOT the same file as the "rabble-entity-rig.html" drifter copies; those three copies (BaBbLE intake, Xperimental drop) are identical to each other but are the older 2026-09 version. The plan's "copies of the same page" row should say: NeBuLA copy is the newer one.
6. Infinity flow: not drawn by any NeBuLA backend (zero hits in src/ for infinity/lemniscate/figure-8). Only alive's "orbit" and the rig SVG's layers hint at it; the Canon says "Infinity flow sits between the two portals" (Unified-Entity-Canon.md:25). So no NeBuLA render currently satisfies the Canon on that point; the Puppet Spec live.js is the only drawer.

## Assessment: alive-backend.js / alive-gl.js
- **alive-gl.js: stay as an internal helper of alive** (a Canvas2D-compatible GL context). If alive is later decomposed it moves to `src/utils/` or becomes the shared "GL 2D context" for the Canvas2D backend (it was written because Firefox/Linux raster canvas ran 11 fps vs 60 on WebGL, alive-gl.js:5-8). Not an entity.
- **alive-backend.js: do not merge now; keep as a named backend and make it the first registry consumer.** Reasons: (a) it is what the Portal actually mounts (below) and the shipped, tuned, perf-tested look (test/alive.perf.mjs, alive.playwright.mjs); (b) its geometry/draw-order code (face rig of 4 ellipses :200-362, occlusion :558-596) is closest to the Puppet Spec portal-occlusion rules, so it is a better seed for the registry than canvas2d's hardcoded constants; (c) canvas2d and threejs are the stale pair: last touched 2026-07, no mood/emotion/boot-host/infinity. Recommended direction: registry -> one geometry+layer description -> alive (2D, 3D) renders it; canvas2d/threejs then either shrink to profile presets of alive (lite/full) or are retired once World's Catalog page stops using the bare default. Merging alive's 1223 hand-written lines into canvas2d's module system before the registry exists would repeat the drift.
- Cost to watch: eye-behavior.js (gaze FSM) and alive's own gaze logic are two implementations of the same soul; reconcile via registry gaze params.
