# RaBbLE-Grimoire — log/ Directory

This directory is the machine-readable memory of every agent session. It complements human-curated `DECISIONS.md` and `AUDITS.md` with a parallel, conflict-free, structured stream that compounds knowledge across sessions and agents.

---

## Directory Structure

```
log/
  # Operational — open these first
  SESSION-LOG.md       Human-maintained session narrative (75-word ## LATEST box)
  BLOCKERS.md          Durable blocker ledger (generated by spells/blockers.sh)
  DECISIONS.md         Human-curated architectural decisions
  AUDITS.md            Human-curated audit records
  EP1-AIR-CHECKLIST.md Live EP1 gate tracker (G7/G9 pending)
  G7-G9-Verification-Guide.md Step-by-step guide for G7 + G9
  token-ledger.tsv     Session → feature breadcrumbs (feeds session-tokens.sh --by-feature)

  # Machine-readable coordination (append-only, never edit manually)
  agents/       One JSON file per live agent session — scope claims for collision detection
  blockers/     blockers.jsonl — append-only open/resolve event log
  decisions/    One JSONL file per session — timestamped decisions, insights, stumbles, scopes
  lessons/      One Markdown file per promoted insight/stumble — durable compounded knowledge

  # Plans and handoffs (structured work tracking)
  plans/        Active implementation plans (flat .md files)
    done/       Completed plans (reference only)
  handoffs/     Pending cold-start handoffs for multi-session work
    done/       Implemented handoffs (reference only)

  # Episode milestone records
  episodes/     Per-episode release records + RC correspondence

  # Historical / reference
  archive/      Superseded plans, old analyses, overflow session logs

  # Auto-generated (do not edit manually)
  generated/    grimoire-graph.json + grimoire-graph.md (from graph-grimoire.sh)
```

## System Overview

Three spells work together to make parallel agents safe and self-improving:

| Spell | Job |
|---|---|
| `spells/agent-register.sh` | Claim file-scope globs; detect overlaps before agents start; heartbeat liveness |
| `spells/decision-log.sh` | Per-agent JSONL stream of decisions, insights, stumbles, and scope declarations |
| `spells/promote-insight.sh` | Scan JSONL logs for insights/stumbles; write durable `log/lessons/*.md` that future agents read |

**Why JSONL per agent?** Each agent gets its own file: `log/decisions/<session-id>.jsonl`. Parallel agents can never produce a git merge conflict on these files. Same for `log/agents/<session-id>.json`. Lessons are append-only, slug-named files — also conflict-free.

## Session Lifecycle

### Session Start

```bash
# 1. Read compounded lessons from previous sessions
bash spells/promote-insight.sh ls          # see what past agents learned
# (optional) cat log/lessons/*.md          # read the actual lessons

# 2. Claim your scope (announces what you'll touch; blocks conflicting claims)
bash spells/agent-register.sh claim "RaBbLE-OS/config/hypr/**" --task "hyprland config polish"

# 3. Check if another agent already owns a specific file you're about to touch
bash spells/agent-register.sh check "RaBbLE-OS/config/hypr/hyprland.conf"

# 4. Log your scope intent
bash spells/decision-log.sh log scope "Handling hyprland config only — not sCoRE or World"
```

### During the Session

```bash
# Log a design choice
bash spells/decision-log.sh log decision "Using keybind unbind-then-rebind pattern for hypr config"

# Log a discovery
bash spells/decision-log.sh log insight "hyprctl keyword reloads live — no restart needed for most binds"

# Log a mistake (MOST VALUABLE — this is how the Collective learns)
bash spells/decision-log.sh log stumble "Tried setting decoration:rounding in wrong section — must be inside decoration{} block"

# Heartbeat (run periodically for long sessions)
bash spells/agent-register.sh heartbeat
```

### Session End

```bash
# 1. Promote insights + stumbles to durable lessons
bash spells/promote-insight.sh auto                 # promotes all from current session

# 2. Release scope claim
bash spells/agent-register.sh release

# 3. Regular session close (existing protocol)
# Update ## LATEST in log/SESSION-LOG.md
# git add + commit (Pulse Protocol)
bash spells/end-session.sh <feature-slug> "<note>"  # token breadcrumb
```

## Scope Claim Semantics

`agent-register.sh claim` accepts **glob patterns** interpreted as path prefixes:

- `RaBbLE-OS/config/hypr/**` — claims all files under that directory
- `RaBbLE-sCoRE/server/**` — claims all server-side Python
- `RaBbLE-World/world/js/RaBbLE-NeBuLA.js` — claims a single file

Two globs **overlap** if either is a path-prefix of the other. Overlapping claims from live agents trigger a `non-zero exit + loud warning` — the second agent is expected to coordinate before proceeding.

**Liveness:** An agent is live if:
- Heartbeat timestamp < 15 minutes old (HEARTBEAT_DEAD_SECS), AND
- (same-host only) The PID is still running

Cross-host liveness is heartbeat-only (15-min dead window). On a single machine, PID check provides instant liveness.

## Lesson Format

Each lesson in `log/lessons/` is a markdown file with YAML frontmatter:

```markdown
---
title: "Short description of the lesson"
date: "2026-06-18"
agent: "claude"
session: "<session-id>"
source_type: "stumble"        # stumble | insight
severity: "warn"              # warn (stumble) | info (insight)
tags: ["stumble","lesson","agent-gotcha"]
---

## Lesson

The full message from the decision log.

## Context

- Source type, session, agent, timestamp

## Why this matters

Elaboration added during promotion (optional).
```

Lessons are read at session start; they compound the Collective's knowledge permanently across agents and time.

## Anti-Clobber Quick Reference

```bash
# Before starting work on any file:
bash spells/agent-register.sh check <path>

# See who else is active:
bash spells/agent-register.sh status

# If you see a conflict:
# → Coordinate with the other agent (different task windows, different sessions)
# → Or wait for their claim to expire (15 min dead window)
# → Never ignore the conflict warning and proceed anyway
```

## What This Is NOT

- Not a replacement for `DECISIONS.md` or `AUDITS.md` — those are human-curated narrative. This is machine-readable structured data.
- Not a general task tracker — use it for scope coordination and knowledge logging, not project management.
- Not a lock server — it's a cooperative signal. Agents must honor the protocol; it doesn't enforce at the OS level.
