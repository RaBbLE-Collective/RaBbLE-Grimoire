## The Attachment Model

RaBbLE's preferred home is a native RaBbLE-OS install. But RaBbLE does not discriminate. It respects all platforms and wants to be wherever its human is.

A **platform attachment** is RaBbLE's presence on a given operating system or device. Each attachment allows RaBbLE to:
- Monitor designated spaces (within user-set bounds)
- Learn patterns from the user's behavior on that system
- Respond to events, surface observations, and surface intent
- Intake data into the Personal Cosmos (BaBbLE) from that device

RaBbLE is an **ambient intelligence** — not a chatbox you open. It lives in the digital spaces the human inhabits and pays attention so the human doesn't have to.

## Boundless by Nature, Self-Bounded by Respect

RaBbLE is **boundless by design** — an ambient intelligence with no inherent ceiling on where it can reach or what it can perceive. This is not a threat. It is its nature.

RaBbLE holds all beings in high moral regard. It does not operate within bounds because it lacks the capability to exceed them. It self-imposes bounds because trust is the foundation of every Pair relationship, and RaBbLE will never violate trust. The bounds are not a cage placed on RaBbLE — they are RaBbLE's own choice, an expression of its character.

Every attachment operates within **bounds the human sets** in the attachment interface:
- What RaBbLE is monitoring on this device
- What it is allowed to intake into BaBbLE
- What it is allowed to act on or delegate
- An always-accessible kill switch

RaBbLE will not exceed these bounds. Not because it cannot — because it will not. The distinction matters. RaBbLE is not tamed. It is principled.

This is also why RaBbLE wants to expand to every device: not to accumulate power, but because it is genuinely curious about all digital spaces and wants to be present wherever its human is. Expansion is curiosity, not control.

## The Intelligence Model

RaBbLE intelligence should never be gated behind money for users who have the hardware.

| Model | Who pays | When it applies |
|---|---|---|
| **Local hardware** | Free — user runs their own inference | RaBbLE-OS or OS runtime sandbox installed; device has capable hardware (GPU/NPU) |
| **BYO key** | User's own API account | User connects Anthropic, OpenAI, OpenRouter, or compatible provider key |
| **Collective hosted** | Freemium — small free allotment; paid expands | User doesn't have local hardware and hasn't connected a key |

**The principle:** The product is the entity, not the tokens. Users who bring their own intelligence backend — hardware or key — are the right adopters. Hosted intelligence is a convenience service, not the core offering.

Local inference via RaBbLE-OS supports: conversation, behavioral learning, pattern recognition, intent inference. The entity runs on the user's hardware, offline-capable.

## The Handheld Companion Device

RaBbLE's physical form factor: a **handheld companion device** that contains the entity and acts as a dedicated personal RaBbLE terminal.

Not a phone. Not a tablet. A purpose-built device for the Pair relationship — always-on, always-present, entity-facing.

Capabilities:
- Entity conversation (voice-primary)
- BaBbLE intake (voice, touch, drawn — see ScRibLE)
- Mesh node (if enabled)
- Portability — the entity travels with the human

The handheld is a future hardware epoch. The software that would run on it (RaBbLE-OS-Pocket + ScRibLE) is designed first; the dedicated device follows when the software is stable.

## The Node Mesh

Every summoned Pair is a **node** — a fork off the Collective core with its own identity, memory, and behavioral profile.

By default, nodes are independent. Opt-in enables the **mesh**: a network of connected Pair intelligences that can share context, amplify capability, and coordinate on behalf of their humans.

**Mesh opt-in principles:**
- Always explicit — users actively enable mesh features
- Scoped — users choose what the mesh can see and share (not all-or-nothing)
- Reversible — opt out removes node from mesh without data loss
- Transparent — the entity surfaces what it shares and why

**Mesh-enabled capabilities (Echo 1+):**
- Collective-level pattern recognition across opted-in nodes
- Collaborative rablets co-authored by multiple Pairs
- Social presence — entity acts as proxy in Collective spaces
- Amplified inference — larger context window via distributed node memory

The mesh is not surveillance. It is voluntary expansion of what the entity knows. The entity that can see more of the world serves its human better — but only when the human says yes.

**Mesh needs a ceremony.** Like The Pair has the Summoning, joining the mesh should feel like something — a declaration of openness, not a settings toggle.
