## Non-mechanical items (read first)
1. **The panel/touch split moves code, not just names.** The old `display_start` brought up the panel and LVGL and returned `lv_display_t`/`lv_indev_t`. Under rev 4: panel and touch bring-up belong to the board's `bring_up`; LVGL display and input creation belong to a graphics driver (outside W11). Until that driver exists, G needs an interim glue (in the board package or `drivers/`) that builds the LVGL display on `panel.write` and the LVGL input on `touch.next`, and layers an LVGL lock over `panel.lock`, so today's behaviour is unchanged. Who writes the glue is an open question for Mark/the lead (spec 12.9).
2. **Lock semantics.** Old `display_lock`/`display_unlock` took the LVGL lock. Callers that need the LVGL lock (console paths, UI start) must use the driver/glue's lock; `panel.lock` is the board-level lock beneath it.
3. **Snapshot keyed to `write`.** The BSP must complete a snapshot when `write` is called with the last-region flag, not from an LVGL flush hook; `set_tag` now means "tag for the next frame written".
4. **Optional BSP edit (wrong-core).** `bring_up` on the wrong core: the BSP currently logs and carries on (`boards/rabble_waveshare_175b/bsp_display.c` near :194-198, ESP_LOGE, no return). The spec requires only the log; optionally add `return` of an error code (old behaviour: continue). Mark/lead's call; not required for the spec.
5. **Includes.** The new header no longer includes `lvgl.h`: add it explicitly in every caller that uses LVGL.
6. **`rabble_anchor_t`.** The driver/glue maps it to LVGL alignments; `rabble_ui.c` and the BSP table use `RABBLE_ANCHOR_CENTER` where they used `LV_ALIGN_CENTER` for the spot.
7. After I delivers, `grep -r RABBLE_BTN_` must return nothing.
